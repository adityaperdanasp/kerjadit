# VPS scripts (WhatsApp listener toolkit)

Reference copies of the scripts that run on the VPS at `ubuntu@43.173.12.98:/home/ubuntu/wa-crm/`.
The dashboard in this repo never imports them — they talk to Notion directly, and the app
only ever sees their output. They live here so the fixes are version-controlled instead of
existing solely on a box with no backups.

**These are copies, not the deployment.** Editing a file here changes nothing until it's
copied up and the service restarted:

```bash
scp vps/listener.js ubuntu@43.173.12.98:/home/ubuntu/wa-crm/listener.js
ssh ubuntu@43.173.12.98 "cd /home/ubuntu/wa-crm && node -c listener.js && sudo systemctl restart wa-listener"
```

Always `node -c` before restarting — a syntax error takes the listener down until someone notices.

## What each one does

| Script | Trigger | Role |
|---|---|---|
| `listener.js` | `wa-listener.service` (systemd, always on) | Long-lived Baileys socket. Read-only: never sends, never marks read, never sets presence. Appends live messages/contact names to `store.json` and posts the Notion heartbeat every 3 min. Does **not** write contact rows to Notion. |
| `daily-sync.js` | cron `0 6 * * *` (Asia/Shanghai) | Reads `store.json`, recomputes days-since-chat and Hot/Warm/Cold for every contact, writes the changed ones to Notion. This is the only thing that moves contact data into Notion. |
| `fetch-history.js` | manual, one-shot | Re-pairs via QR and bulk-imports chat history into `store.json`. Used for first setup and for recovering a gap after a broken session. Exits on its own once history stops arriving. |

## Files on the VPS that are deliberately NOT copied here

| Path | Why it stays there |
|---|---|
| `.env` | `NOTION_TOKEN` and friends. |
| `auth_info/` | Live WhatsApp session keys — equivalent to a logged-in device. |
| `store.json` | Real message text from private chats. ~1 MB and personal; keep it off GitHub. |
| `clusters.json` | Last-sync snapshot, includes message summaries. |
| `notion-page-map.json` | `jid → Notion page id`. Not secret, but regenerated by the scripts and noisy in diffs. |

## Data shapes

`store.json` — array, one entry per contact, written by `listener.js`/`fetch-history.js`:

```jsonc
{
  "jid": "628xxxxxxxxxx@s.whatsapp.net", // or "…@lid" (WhatsApp's privacy id)
  "allJids": ["…"],                      // both ids when the same person is known by two
  "name": "Ade Irma Stefi",              // null until WhatsApp reveals a pushName/contact name
  "lastMessageTimestamp": 1786590522,     // UNIX seconds — the field everything downstream keys on
  "messages": [                           // capped at the newest 20
    { "fromMe": false, "timestamp": 1786590522, "text": "…" }
  ],
  "businessProfile": null                 // fetched once, on a contact's first message
}
```

`clusters.json` — array, written by `daily-sync.js`. Its previous contents are the "old" side of
the change detection, so **deleting it makes the next sync treat all 800+ contacts as new** and
push every one of them to Notion:

```jsonc
{
  "jid": "…",
  "last_message_timestamp": 1786590522,
  "days_since_last_chat": 0,
  "cluster": "hot",                 // hot ≤7d, warm ≤14d, else cold
  "company_name": null,             // never overwritten once set (may come from a one-off AI pass)
  "industry": "unknown",
  "client_type": "unknown",
  "summary": "(pesan terakhir) …",
  "suggestion": "…"
}
```

`notion-page-map.json` — flat `{ "<jid>": "<notion page id>" }`. A jid missing here makes
`daily-sync.js` **create** a new Notion page instead of updating; losing this file would
duplicate every contact.

## Two behaviours worth knowing before changing anything

- `daily-sync.js` writes a **reduced** property set to existing pages (`buildUpdateProperties`):
  cluster, days, summary, suggestion, update-time. Nama/Perusahaan/Industri/Tipe Client are
  written **only on page creation**, so manual corrections in Notion are never clobbered.
- Everything downstream is a pure function of `store.json`. If Notion looks wrong, check
  `store.json` first: matching = the sync just hasn't run; not matching = the listener is the problem.
